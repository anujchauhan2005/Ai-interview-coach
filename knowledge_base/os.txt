== OPERATING SYSTEMS ==

--- BASICS ---
- OS: software that manages hardware resources and provides services to programs
- Types: Batch OS, Time-Sharing OS, Distributed OS, Real-Time OS, Mobile OS
- Kernel: core of OS — manages CPU, memory, I/O devices
- Kernel space vs User space: kernel runs in privileged mode, user apps in restricted mode
- System calls: interface between user programs and kernel (fork, exec, read, write, open)

--- PROCESS vs THREAD ---
- Process: independent program in execution with its own memory space (code, data, stack, heap)
- Thread: lightweight unit within a process, shares memory with other threads in same process
- Process creation: fork() creates child process (copy of parent)
- PCB (Process Control Block): stores process state, PID, program counter, registers, memory info
- Context Switch: saving state of current process and loading state of next process
- Inter-Process Communication (IPC): Pipes, Message Queues, Shared Memory, Sockets, Semaphores
- Thread vs Process: threads faster to create (no memory copy), but shared memory = risk of race conditions

--- PROCESS STATES ---
New → Ready → Running → Waiting → Terminated
- New: process being created
- Ready: waiting for CPU
- Running: executing on CPU
- Waiting: waiting for I/O
- Terminated: finished execution

--- CPU SCHEDULING ---
- Goal: maximize CPU utilization, minimize waiting time, turnaround time, response time
- FCFS (First Come First Serve): non-preemptive, convoy effect
- SJF (Shortest Job First): non-preemptive, minimum average waiting time, starvation possible
- SRTF (Shortest Remaining Time First): preemptive SJF
- Round Robin: preemptive, time quantum, good for time-sharing
- Priority Scheduling: can be preemptive or non-preemptive, starvation possible
- Multilevel Queue: different queues for different process types
- Aging: technique to prevent starvation by gradually increasing priority

--- SYNCHRONIZATION ---
- Race Condition: multiple processes access shared data simultaneously, outcome depends on order
- Critical Section: code segment accessing shared resources
- Mutex (Mutual Exclusion): lock allowing only one thread at a time
- Semaphore: integer variable for signaling. Binary semaphore = mutex. Counting semaphore
- Deadlock: set of processes blocked, each waiting for resource held by another
- Deadlock Conditions (all 4 must hold): Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait
- Deadlock prevention: eliminate one of the 4 conditions
- Deadlock avoidance: Banker's Algorithm
- Deadlock detection and recovery: kill process or preempt resources
- Monitor: high-level synchronization construct (used in Java)
- Producer-Consumer, Reader-Writer, Dining Philosophers: classic synchronization problems

--- MEMORY MANAGEMENT ---
- Logical Address (Virtual): generated by CPU, used by process
- Physical Address: actual RAM location
- MMU (Memory Management Unit): translates logical to physical address
- Fragmentation:
  - Internal: allocated memory larger than needed (fixed partitioning)
  - External: free memory scattered, not contiguous (dynamic partitioning)
- Compaction: move processes to make contiguous free space (expensive)
- Paging: divide memory into fixed-size frames/pages. Eliminates external fragmentation
- Segmentation: divide memory into variable-size segments. Eliminates internal fragmentation
- Page Table: maps logical pages to physical frames
- TLB (Translation Lookaside Buffer): cache for page table entries, speeds up address translation

--- VIRTUAL MEMORY ---
- Allows processes to use more memory than physically available
- Demand Paging: load pages only when needed
- Page Fault: page not in RAM, must load from disk
- Page Replacement Algorithms:
  - FIFO: replace oldest page
  - LRU (Least Recently Used): replace page not used for longest time (best in practice)
  - Optimal: replace page not needed for longest future time (theoretical best)
  - LFU (Least Frequently Used): replace least accessed page
- Thrashing: process spending more time paging than executing (too many page faults)
- Working Set Model: keep the set of pages a process needs to avoid thrashing

--- FILE SYSTEM ---
- File: named collection of data stored on disk
- Directory: organizes files in tree structure
- File Allocation: Contiguous, Linked, Indexed
- FAT (File Allocation Table), NTFS, ext4, APFS: common file systems
- Inode: data structure storing file metadata (size, permissions, location on disk)
- Hard Link vs Soft Link (Symbolic Link)
- Disk Scheduling: FCFS, SSTF, SCAN (Elevator), C-SCAN, LOOK

--- I/O MANAGEMENT ---
- Polling: CPU continuously checks device status (busy waiting)
- Interrupts: device signals CPU when operation complete (efficient)
- DMA (Direct Memory Access): device transfers data directly to RAM without CPU
- Buffering, Spooling, Caching: techniques to improve I/O performance
